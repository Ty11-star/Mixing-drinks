调酒小程序「调一杯」项目过程

这项目就是做一个教人调酒的小程序，能看酒谱、搜酒谱，手头有什么材料就告诉你能调什么酒，还能让 AI 帮忙配一杯。

东西分三块：
小程序——装在手机上给用户看的；
后台管理——在电脑浏览器里用，录酒谱、材料、分类，看用户；
服务器——两边都靠它存数据和取数据。


一、怎么一点点做出来的

1、先想清楚要做啥、长啥样
先把功能和页面在文档里定下来，颜色也定了：酒的金色，加酒吧那种深蓝。这样后面照着做，不至于每个人做的风格都不一样。还顺手放了一套开发流程的规范（.claude/skills），照着它一步步来。

2、把要存的东西理清楚（数据库）
酒谱、材料、每种酒要用哪些材料、做法步骤、分类、用户、管理员。先写了两份 SQL 当草稿。
真正建表是一键脚本建的，顺便把默认账号 admin / 123456、12 个分类、36 种材料塞了进去。后来嫌材料少，又补了 30 多种，现在材料库里 60 多种。

3、写服务器（后端）
按层分着写：管数据的、管业务的、管接口的、管登录的。统一了返回格式，加了登录校验、出错提示、允许跨域。
现在能做的事：登录，酒谱的增删改查和搜索，材料的增删改查，分类的增删改查，小程序用户管理，后台首页的统计。

4、写后台管理（电脑上用）
先做登录、登录状态、请求封装，再一个个页面做：首页统计（带图表）、酒谱管理（列表加编辑表单，能加材料、加步骤、选分类）、材料管理、分类管理（基酒 / 口味 / 场合三个标签）、用户管理。
图标、加载动画、空页面提示都是自己画的一套，风格统一。

5、写小程序
一共 9 个页面：首页、酒谱详情、分类、搜索、搜索结果、AI 配方、调一杯、知识、我的。底部四个菜单：首页 / 调一杯 / 知识 / 我的。
首页能切两种排法，能按基酒筛，能下拉刷新、往下滑加载更多。详情页把材料用量画成比例条，能收藏，看过的会记下来。搜索有热门词和搜过的记录。「调一杯」最花心思：点材料就往杯子里倒，不同材料颜色不一样会一层层叠起来，还能摇一摇直接让 AI 配。AI 给的配方能复制，也能存进酒谱库。知识页放了基酒、方法、工具、术语、单位换算。我的页面能微信登录、换头像改昵称、看收藏和历史。

6、接 AI
用 DeepSeek 来配酒，提前跟它说好只回固定格式：一份配方、几个备选玩法、一句话说明。点保存会把配方存进酒谱库，材料库没有的会自动补上，重名的不会重复存。

7、收尾
补了底部菜单选中效果、知识页和我的页的数据、调一杯的动画、假数据，最后把每个页面从头到尾点了一遍。


二、怎么把它跑起来

（1）启动后端
cd server
npm install
npm run init-db      第一次用，建表并写入初始数据（会清空旧数据）
npm run dev

（2）启动后台管理系统
进入 manage 并安装项目依赖
cd manage
npm install 或者 npm i

启动后台管理
npm run dev

然后打开 http://localhost:3001，账号 admin，密码 123456。

（3）打开小程序
用微信开发者工具打开 miniprogram 文件夹
把里面配置的接口地址改成自己电脑的地址
在「详情 - 本地设置」里勾选「不校验合法域名」
服务器没开的时候，把配置里的 useMock 改成 true，先用假数据看页面


三、踩过的大坑

1、数据库名字里有空格
库名是 Mixing drinks，中间有个空格，直接写 SQL 就报错。后来在名字两边加上反引号才解决。

2、后台端口，两份文档写得不一样
一个写 5173，一个写 3001。实际用的是 3001，就把文档按 3001 改，不然联调时老找错地方。

3、前后端端口不一样，浏览器不让请求
后台 3001，服务器 3000，直接请求会被拦。让服务器允许跨域，接口地址统一写在配置文件里，不散在代码里。

4、小程序连不上自己电脑上的接口
小程序会检查域名，用 localhost 会被拦。勾上「不校验合法域名」，接口地址统一放一个文件里，方便换成电脑的局域网 IP。另外做了个开关，服务器没开就用假数据看界面。

5、AI 有时候不好好回内容
偶尔会多包一层代码块，或者前面加一段说明，直接读就出错。就要求它只回 JSON，读失败提示「格式解析失败」，内容不全提示「数据不完整」，页面给重试，不会白屏。

6、AI 的钥匙没填，报错看不懂
调用前先检查有没有配置钥匙，没有就直接说「没配置 AI 密钥」，省得当成网络问题查半天。

7、AI 配的酒存不下来
一开始只在页面上显示，关掉就没了，后面「找找能调什么」里也搜不到。后来加了保存，存的时候把酒谱、材料、步骤一起写进去，材料没有就自动加，重名的不重复存。

8、设计表时的 SQL 和实际建的表对不上
最早写的 SQL 有 10 张表，真建的时候是 8 张，状态字段的 0 和 1 意思还反着。后来统一按代码里的表为准，那份 SQL 只当参考，不然照着旧字段写查询会错。

9、一键建库的脚本会清空数据
每次跑都删表重建。所以只在第一次用，后面补数据用另外的小脚本，有重要数据先备份。

10、文档写的技术版本和实际装的不一样
文档写 React 18、Ant Design 5，实际装的是 React 19、Ant Design 6。以实际装的为准，后面把文档改过来。


四、顺手记的小毛病

这些毛病不大，但用的时候能感觉到，先记着以后顺手修：

1、手机上首页往下拉想刷新，结果没反应。翻代码发现页面没开下拉刷新那个开关，方法写了也白写。
2、分类列表里图标全是裂开的小图。因为一开始给分类填的图片地址是 /images/xxx.png，但项目里压根没放这些图片，自然显示不出来。
3、删分类、删材料时不会先看看下面还挂着酒谱没有，直接就删了，酒谱那边的关联就空了。
4、详情页点收藏没有任何提示，不知道到底收没收藏成功。
5、酒谱详情想显示封面图，但数据库里压根没存封面这个字段，所以现在封面位置只能拿渐变色块加个酒杯图标顶着。
6、AI 配完酒点保存，保存完就完了，不提示「去哪里看」，用户容易以为没存上。
7、材料匹配结果只说「能调」，不说还差哪几样材料，用户得自己对着清单比一遍。
8、知识页那些基酒、工具介绍全是写死在代码里的，想加内容或改字得动代码，后台没法维护。
9、我的页面登录之后没退出登录的入口，想换号只能点「重新登录」覆盖掉。
10、搜索只能按酒谱的名字搜，输「伏特加」「清爽」这种基酒名或口味名搜不到对应酒。
11、换电脑或真机调试时，要把代码里一行接口地址改成电脑的 IP，没有更省事的办法。
12、小程序里头像、收藏、历史都存在手机本地，换个手机就没了。


五、现在做到哪了

后端：表建好了，登录、酒谱、材料、分类、用户、统计、AI 都能用。
后台：登录、首页统计、酒谱管理、材料管理、分类管理、用户管理都能用，跟后端通了。
小程序：9 个页面都能跑，走的是真接口，也有假数据兜底。
AI：选材料、看配方、复制、存进酒谱库，一整套能用。
数据：管理员 1 个、分类 12 个、材料 60 多种，酒谱自己在后台录。


六、还没做的（对应参考图第 5～8 条）

1、材料分类是写死的
现在前后端各写了一份「基酒 / 利口酒 / 果汁 / 糖浆 / 装饰 / 其他」，要改成单独一张表，后台能自己加，新增材料时的下拉和筛选都从接口拿。
2、新增材料时「所属分类」的下拉来源要统一
材料那边是固定选项，酒谱那边是从分类表读的，两套逻辑。改成从表里读以后，分类表空了下拉就没东西选，要提示「先去分类管理添加」，再给个默认分类兜底。
3、新增分类时，弹窗里的「图标URL」只能手填地址
现在就是个输入框，服务器也没有上传图片的功能。要改成选图片上传，后台存好图，表单里只放图片地址。
4、图片上传完不回显
选完图要能看到缩略图，编辑时也要把原来的图显示出来，列表里也显示图标，不然不知道传没传上。
5、酒谱封面图
详情页已经留了显示图片的位置，但数据库没这个字段，要加字段，后台能传图，接口把图片地址返回。
6、安全和收尾
管理员密码还是明文，要加密；一键建库脚本要改增量，别一跑就清数据；AI 生成的内容加个审核状态。

小程序：miniprogram，配置在 app.json
